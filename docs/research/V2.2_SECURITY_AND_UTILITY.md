## Requirement representation (WP-4)

Each stated requirement keeps: the request span, the normalized proposition ("has lanyard loop", "has no ads"),
polarity (REQUIRED/EXCLUDED), strength (MUST/NICE), the evidence capability (`unrecognized:<slug>` for an
unfamiliar one), claim type (PROPERTY or PERFORMANCE), provenance (request text or structured input) and a note
(DECORATIVE, CATEGORY_WORD). Per product, the ledger reports the verification state, bound to that product id:

- VERIFIED: manufacturer page (a stated property) or two independent expert groups (any claim; required for a
  performance claim), with the counted source URLs; or CATALOG_IDENTITY when a one-word requirement is the listing's
  own brand or model word.
- CONTRADICTED: evidence shows this product fails it (a known violation, never resolvable in the session).
- UNVERIFIED: open (no attributable statement, too few sources, or sources disagree).
- OWNER_ATTESTED / OWNER_WAIVED: the owner's own statement or waiver, through the passkey flow, with a caution that
  it is not independently verified. A confirmation sends the session back to HOLD with the comparison cleared, so a
  fresh compare (quote and eligibility) is required; the spending maximum and mandate limits are unchanged.

## Owner-key-only routes (WP-2 review item)

`/authorize`, mandate creation, the browser handoff page and the MOCK approval page are disabled unless service
isolation is established, like checkout preparation. They still authenticate with the owner key (plus cookie and
CSRF) and not with a passkey; requiring the passkey there (R-A-1 / SR-01) remains a precondition for any
deployment.

## Remaining risks

- The proposition matcher is lexical: a paraphrase ("a loop for a lanyard") is not recognized (fails closed:
  UNVERIFIED), and a statement that uses the same words with another meaning could verify a proposition. Statements
  still need the exact model, a counted source and attribution to this product.
- A one-word requirement equal to the listing's brand or model word is satisfied by the catalog identity; a user who
  meant a feature with the same word as the brand would not be asked.
- Approximate budgets are applied as the maximum; a user who meant "a little over is fine" is held to the amount.
- Isolation is checked at startup only; changes to permissions while the server runs are not detected until restart.
- macOS service-account setup is manual and was not tested.
